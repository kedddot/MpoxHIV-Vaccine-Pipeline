================================================================================
MpoxHIV PIPELINE -- COMPLETE TOOL INSTALLATION
Every external dependency of Phases I, II and III. macOS / Linux, conda-based.
================================================================================

The pipeline uses FOUR conda environments because the tools have mutually
incompatible dependencies (Aggrescan3D is Python 2.7; MHCflurry pins numpy 2.x
while OpenMM/pdbfixer need numpy 1.26). Do not try to merge them.

Scripts locate every binary through an environment variable with a hardcoded
default (see Section 6). If you install anywhere other than the paths below,
export the matching variable instead of editing code.


================================================================================
0. IF YOU ARE ON **THIS** MACHINE -- ALREADY RELOCATED TO THE SSD
================================================================================
As of 2026-08-28 every dependency below already lives on the external volume
"Extended SSD". You do not need to install anything. Just run:

    source ~/mpoxhiv_env.sh

before any pipeline step. That sets every path in Section 6 for you. Add the
line to ~/.zshrc to make it permanent.

  On the SSD now:
    /Volumes/Extended SSD/phenix-2.2-6143/              14 GB
    /Volumes/Extended SSD/MpoxHIV_deps/envs/{phase2,mhcpredict,a3d,apbs_env}
    /Volumes/Extended SSD/MpoxHIV_deps/mhcflurry/       425 MB
    /Volumes/Extended SSD/MpoxHIV_deps/huggingface/     130 MB

  THE VOLUME NAME CONTAINS A SPACE, AND THAT MATTERS. A shebang line cannot
  contain a space -- the kernel splits on whitespace, so
  "#!/Volumes/Extended SSD/.../python3.11" resolves to interpreter
  "/Volumes/Extended" and every Python entry point fails with
  "bad interpreter". Compiled binaries (blastp, apbs) are unaffected, which
  makes this fail in a confusing, partial way.

  The fix in place: ~/mpoxhiv_ssd is a space-free symlink to the volume, and
  all four conda environments were cloned to paths underneath it. Keep that
  symlink. If you ever move the envs again, the destination path must contain
  NO SPACES.

  Sections 1-9 below remain the record of how to rebuild from scratch on a
  different machine.

================================================================================
1. THE FOUR CONDA ENVIRONMENTS  -- 4 commands
================================================================================
Prerequisite: Miniconda/Anaconda installed at /opt/miniconda3 (or adjust paths).

# --- ENV 1: mhcpredict -- MHC-I/II binding prediction (Phase 1Da, 1F) -------
conda create -y -n mhcpredict -c conda-forge python=3.11 && \
  /opt/miniconda3/envs/mhcpredict/bin/pip install \
    mhcflurry==2.2.1 mhcnuggets==2.4.1 tensorflow numpy pandas torch && \
  /opt/miniconda3/envs/mhcpredict/bin/mhcflurry-downloads fetch

# --- ENV 2: phase2 -- the main workhorse env (most of Phases 1E, 2, 3) ------
# Only blast and apbs come from conda here. Everything else is pip -- verified
# against this env's own conda-meta/history, not assumed. Do NOT try to conda-
# install openmm/pdbfixer/pdb2pqr; the working env has them from pip and the
# conda builds pull a different numpy.
conda create -y -n phase2 -c bioconda -c conda-forge python=3.11 blast apbs && \
  /opt/miniconda3/envs/phase2/bin/pip install \
    "numpy==1.26.4" openmm==8.6.0 pdbfixer==1.12.0 pdb2pqr \
    biopython==1.88 freesasa==2.2.1 pydssp==0.9.1 pandas requests \
    scikit-learn torch transformers datasets \
    toxinpred2==1.1 hemopi2==1.3

# --- ENV 3: a3d -- Aggrescan3D standalone, Python 2.7 ONLY (Phase 2C) -------
# aggrescan3d is NOT on PyPI for py2.7 -- it comes from the lcbio conda channel.
conda create -y -n a3d -c conda-forge python=2.7 && \
  /opt/miniconda3/bin/conda install -y -n a3d \
    -c lcbio -c bioconda -c conda-forge aggrescan3d

# --- ENV 4: apbs_env -- APBS electrostatics (Phase 2C) ----------------------
conda create -y -n apbs_env -c bioconda -c conda-forge apbs


================================================================================
2. LOCAL BLAST DATABASES  -- 2 commands
================================================================================
Both are built from UniProt REST downloads. Run from the project root.

# --- Human Swiss-Prot, for the self-homology screen (Phase 1Ec) ------------
# ~20,431 reviewed human sequences.
mkdir -p human_swissprot_db && cd human_swissprot_db && \
  curl -o human_swissprot.fasta \
    'https://rest.uniprot.org/uniprotkb/stream?query=reviewed:true+AND+organism_id:9606&format=fasta' && \
  /opt/miniconda3/envs/phase2/bin/makeblastdb -in human_swissprot.fasta \
    -dbtype prot -out human_swissprot && cd ..

# --- UniProt Tox-Prot, for the toxicity screen (Phase 1Ea, 2A) -------------
mkdir -p toxprot_db && cd toxprot_db && \
  curl -o toxprot.fasta \
    'https://rest.uniprot.org/uniprotkb/stream?query=reviewed:true+AND+keyword:KW-0800&format=fasta' && \
  /opt/miniconda3/envs/phase2/bin/makeblastdb -in toxprot.fasta \
    -dbtype prot -out toxprot && cd ..


================================================================================
3. BigMHC -- IMMUNOGENICITY (Phase 1Dd)  -- 1 command
================================================================================
Cloned, not pip-installed. Runs under the phase2 env's python.

mkdir -p external_tools && git clone https://github.com/KarchinLab/bigmhc.git \
  external_tools/bigmhc

*** DO NOT DELETE external_tools/bigmhc/models/bat*/el/ ***
Only `-m=im` (immunogenicity) is used, but each bat*/im/ directory contains
just 4 retrained condenser layers and loads the other 32 from the co-located
el/ base. Removing el/ silently breaks BigMHC. This is ~2.4 GB and it is
load-bearing.
