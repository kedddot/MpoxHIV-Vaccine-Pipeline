Both mirror their original locations under Step_Outputs/, so ANY entry can be
restored by copying it back along the same relative path.

NEITHER IS READ BY THE PIPELINE. Every input selector uses os.listdir() or
glob.glob() WITHOUT recursion and filters on ".csv"/".fasta"; a directory whose
name carries no such extension is invisible to all of them. Verified by calling
each resolver directly after archiving.

WHAT IT IS
  The full Phase I + II + III result set for Vax_Final_0c83e66a (484 aa), as it
  stood immediately before Phase 1Eb's allergenicity combination rule was
  changed from OR to CONSENSUS (deviation #24).

WHY IT WAS KEPT RATHER THAN SUPERSEDED
  The construct that replaced it was produced by a different decision rule, not
  a rerun. Under the old rule a peptide was excluded if EITHER AllerTOP OR
  AllergenFP called it an allergen; measured on the real pool the two disagree
  on 41 of the 70 peptides where both can run (59%) and agree on ALLERGEN for
  only 14. That is close to a coin flip being used as a hard filter, and it cost
  HIV_gp41 every one of its B-cell candidates. Both result sets are therefore
  legitimate under their own stated rule, and both must remain reproducible.

================================================================================
5. RESTORING FROM AN ARCHIVE
================================================================================
Paths mirror the live tree, so restoration is a copy back along the same
relative path. To return to the 484 aa construct:

  cp -R "Step_Outputs/_Baseline_2026-08-28_PreConsensusRule/Phase1/Phase1G/." \
        "Step_Outputs/Phase1/Phase1G/"

and likewise for Phase1E, Phase1F, Phase2, Phase3. Because every step selects
its input by newest timestamp, restoring a file older than the current one will
NOT change what the pipeline picks up -- move or delete the newer file as well
if a genuine rollback is intended.
